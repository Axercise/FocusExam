# Checkpoint 2.3 — Tracks

Approved: create/edit/archive personal subject tracks, persist in Supabase, show
real tracks on Dashboard, and provide a dedicated /tracks management page.

## Delivery

1. Add tracks with owner UUID, name (1–80 characters), optional description
   (up to 280 characters), predefined color/icon, archive and audit timestamps.
2. Enforce ownership for insert/update in RLS and restrict writable columns.
   Admin may read tracks to support the previously approved study-log permission,
   but cannot create/edit/archive another user's tracks. No client hard delete.
3. Add /tracks with active/archived lists, pagination, create/edit dialogs,
   archive/restore, empty states, Thai/English and Light/Dark.
4. Show up to three real active tracks on the signed-in Dashboard. Keep the
   guest demo clearly labelled. Learning time/statistics remain labelled samples
   until the timer/session checkpoint; do not invent study totals for real tracks.
5. Verify DB isolation/validation/permissions with rollback fixtures, then real
   browser CRUD/restore/persistence, empty accounts, navigation and responsive UI.

## Scope boundaries

No timer/session/recap/streak implementation in this checkpoint. No admin data
management UI, new paid services, or changes to account/Google/email settings.
Archived track rows remain intact for future session history. Duplicate names
are allowed; IDs identify tracks. User-entered names do not change with UI language.
