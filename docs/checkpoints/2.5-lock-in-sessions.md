# Seconds, Lock in, and saving study sessions

Approved: second-level countdown settings, unlimited count-up Lock in mode,
and finish/save into a personal Track. Includes optional Recap and real Track
totals. No forced breaks or eight-hour cap; paused time is excluded.

Implementation checkpoints:
1. Server-clock timer runs and immutable, idempotent saved sessions with owner
   access and admin read-only log access. No client-supplied credited duration.
2. Extend the existing timer while preserving older local snapshots; explicit
   legacy/guest messaging for rounds that have no server timing anchor.
3. Save panel with personal active Track selection, optional Recap, retry, and
   archive/foreign-owner protection. Prevent accidental loss of an unsaved round.
4. Real saved Track totals and recent session history, followed by DB/API/browser
   validation (including a QA-only eight-hour run and duplicate saves).

Existing local rounds remain usable, but cannot be promoted to server-verified
history retroactively. New signed-in rounds are timed on the server. No full
daily/streak dashboard or rewards in this change.

Status: complete.

Delivered:
- Countdown duration supports 00:01–180:00 with separate minutes/seconds fields.
- Lock in displays HH:MM:SS and counts up without a scheduled end or forced break.
- Signed-in timer transitions use server-clock RPCs. One unfinished round per
  owner; row ownership and write privileges do not trust browser metadata.
- Finish, select an active personal Track, optional Recap, and save once.
  Breaks may be saved separately without crediting a study Track.
- Unsaved-round reset/next requires explicit discard confirmation.
- Saved totals appear on Dashboard/Track cards; /history shows actual sessions,
  durations and Recaps with owner filtering and pagination.
- Save retries are idempotent by run ID. Credited duration is server-calculated,
  never supplied by the client. Pause intervals are excluded.
- All SQL migrations match remote history; no new dependencies or paid services.

Verification:

- SQL rollback suite passed: simulated eight-hour Lock in, countdown deadline

  A real one-second countdown saved exactly one second; Dashboard updated to
  08:00:01 without reload and retained that total after reload.

  Track picker loaded 25 then all 27 QA subjects, including the oldest subject.

Limits:
- The eight-hour tests use model clocks and trusted QA-only DB fixtures; they
  are not eight hours of physical-device testing.
- A server run proves elapsed time, not whether the user actually studied.
  No attention monitoring or reward system is implemented.
- Signed-in timing controls/saving require a connection. On failure, the round
  remains recoverable; retry after reconnecting. If local cache is cleared,
  Start recovers the account's pending server round rather than creating a duplicate.
- Local pre-upgrade or guest rounds cannot be credited retroactively. This is
  stated in the UI; start a new signed-in round for a savable session.
- Full daily/streak/weekly statistics remain the next checkpoint.
