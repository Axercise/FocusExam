# 2.9 — Track details and subject history

Approved: a dedicated Track page with all-time/today/this-week/this-month
saved study totals, subject-only charts, dated history with Recaps and readable
archived Tracks.

## Contract

- Dashboard cards and Track list links open `/tracks/[trackId]`.
- Track list cards now use the title's native link across the entire card,
  including padding, icon, description and duration. Edit/archive/restore and
  the existing detail button sit above that link and retain separate controls.
  Whole-card keyboard focus is visible. Verified native link hit targets,
  desktop click, Enter navigation, mobile tap and archived-card restore hit
  targets using temporary sample props; no hosted data changes were needed.
  Production build/TypeScript pass; the temporary route was removed (404).
- Fresh authentication and explicit owner checks, including inside a read-only
  SECURITY INVOKER RPC. Foreign/missing/invalid IDs share the unavailable page.
- Reuse existing saved sessions and exact session_day_allocations. No new study
  rows, no timer changes, no changes to the live ten-minute account Streak.
- Summary week is Monday through today; month is first day through today.
  Chart navigation retains existing day / trailing-seven-days / calendar-month
  conventions. Dates follow captured study dates, not the time of saving.
- Each filtered history entry represents one session even if it spans multiple
  selected dates. Show credited time in the selected range and full-round time
  when different. The Recap always belongs to the complete round.
- History can switch between the selected range and all saved sessions, with
  stable server pagination of 12 sessions. Legacy unallocated sessions appear
  only in all-history and all-time totals, with an explanation.
- Breaks have no Track and are excluded. Subject charts show only study time;
  shared full-account charts retain both green study and purple break tooltips.
- Thai/English, both themes, responsive layouts, empty states and archive label.
- Verify real SQL, owner/admin/anonymous boundaries, month/midnight/DST and
  pagination; use isolated temporary fixtures and remove only those fixtures.
