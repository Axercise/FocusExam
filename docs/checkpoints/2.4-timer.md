# Checkpoint 2.4 — Working timer

Approved: working timer, followed by allocation/recap and real statistics in
subsequent checkpoints.

## Delivery

- Focus/break countdowns (25/5 minutes initially); editable 1–180 minute durations.
- Start, pause, resume, finish early, and confirmed reset of unfinished time.
- Compute elapsed time from timestamps, not interval ticks. Recover after reload,
  navigation or a background tab; finish at the actual countdown deadline.
- Persist local state separately for guests and each account. Synchronize tabs;
  use Web Locks when supported for serialized state transitions. Memory fallback
  if browser storage is blocked, with a clear persistence notice.
- Completion summary, accessible in-app notice, best-effort soft sound when
  audio was enabled by a user interaction; no notification permission prompts.
- Preserve native/fallback fullscreen and keyboard navigation, Thai/English,
  Light/Dark, desktop/mobile/landscape.

## Boundaries

Browser-local timer only: not a trusted study record and not cross-device sync.
No database/session/recap/streak writes or rewards. Existing statistics stay
explicitly labelled samples. Starting a new round replaces the local last-round
summary; it does not allocate time to a Track.

## Verification

Complete.

- ESLint, TypeScript and final production build passed.
- 17 unit tests passed: 9 timer tests plus 8 account/track regression tests.
  Timer coverage includes timestamp catch-up, rounding, pause exclusion,
  resume identity, deadline clamping/idempotence, finish early, independent
  focus/break durations, reset/next mode, and malformed storage.
- Clock-driven browser tests passed for start/pause/resume, reload/navigation,
  early completion, exact logical deadline after throttled/late wake-up,
  one completion event, two scheduled chime notes, mute, completion recovery,
  break completion, 120-minute custom duration and invalid duration.
- Two tabs shared running/paused/resumed/reset state. Simultaneous resume kept
  one session identity, one start time from an acting tab, and accumulated time.
- Blocked localStorage and rejected Web Locks used the memory fallback without
  page errors; unsupported randomUUID fallback worked. Reload correctly reset
  the non-persisted timer and the UI explained this limitation.
- Two temporary real Auth QA users and a guest kept three independent timers.
  Refresh, /tracks navigation and returning to an earlier account recovered
  that owner's own paused round. Both QA accounts were signed out and deleted,
  with their sessions/profiles/roles; confirmed zero QA rows and original
  two real accounts intact. Production Track data was not changed.
- 32 fullscreen combinations passed: native/fallback × Thai/English × Light/Dark
  × 375×900, 768×1000, 1440×1000, 812×375. Included 180:00 digit bounds,
  no horizontal overflow, visible exit, focus containment and inert/scroll cleanup.
- 16 final edge-case combinations passed on portrait/landscape: opening custom
  duration while fullscreen keeps the fixed exit toolbar visible; setting
  duration returns focus to Start; keyboard Start keeps focus; Escape dismisses
  reset dialog first; confirmed reset restores focus and fullscreen exits cleanly.
- Final portrait/dark and landscape/light screenshots inspected. No JavaScript
  page errors. Tests simulate elapsed time; not an OS wake-up or audible-speaker
  test, and not a Safari/physical-device test.
